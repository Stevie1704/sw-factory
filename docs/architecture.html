Software Factory architecture

Factory is a headless, host-owned workflow coordinator. It projects durable state into SQLite and GitHub, runs untrusted work in pinned Docker workers, and communicates with Codex or Claude Code through detached process and native-session APIs. Screens and local terminal topology are not part of the correctness model.

Harnesses propose changes and write a structured report through factory-report. The host coordinator alone accepts reports, creates checkpoints, evaluates gates, mutates GitHub, and advances the run.

Invocation and recovery

Each invocation records its worker, harness, role, stage, prompt version, result directory, and harness-native session identity. Recovery compares durable workflow state with Git, GitHub, the worktree, worker process, native harness session, report, and effect journal. Ambiguity pauses the run for reconciliation; no display or notification channel can block progress.

Compatibility boundary

Existing host registrations use schema 1 and contain obsolete local-UI fields. Factory rejects them before mutation with instructions to drain the previous binary, stop its coordinator, and register again. Repository policy remains schema 1. Docker image and mount behavior are unchanged.
